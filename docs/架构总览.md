## 一、全景：三个位置，一条数据流

```
┌─────────── 本机（Windows + RTX 4060 8GB）───────────┐
│                                                      │
│  VibeMemory-中台/（运行副本，Desktop 下）             │
│  ├─ 每天 10:00 计划任务 → daily_runs.py              │
│  │   ①评测 run_eval.py --all（14 套召回评测）         │
│  │   ②测试 run_tests.py --scope full（1,360 用例）    │
│  │   ③监控 collect_runtime_metrics.py（负载采样）     │
│  │   ④增量 scp（marker 水位过滤，只传新文件）────┐    │
│  └─ LLM-judge（GPU 答案级评测，人工触发）         │    │
│     run_answer_eval.py + llm_judge.py（NF4）     │    │
└──────────────────────────────────┼────────────────┘
                     scp / SSH     │
┌──────────── instabox 云服务器（Debian）▼─────────────┐
│  /data/home/VibeMemory-中台（部署副本）               │
│  /data/home/vibe-memory（GitHub 数据仓库克隆）        │
│  /data/home/projects/（知识库 + codex-zcode-team）   │
│                                                      │
│  4 个 systemd 用户服务（Linger 自启/Restart 自愈）：  │
│  · autopull   每 15 分钟轮询 GitHub → 新提交跑流水线   │
│  · zhongtai   8080 大屏 + 12 个数据 API               │
│  · archive    8081 全档浏览                           │
│  · keepalive  保活 + 心跳 + 服务失联自愈重启           │
│                                                      │
│  流水线 server_pipeline.sh：                          │
│  collect → build_assets → quality → pages → signals  │
│                                                      │
│  cloudflared ×2 隧道 → 公网大屏 / 档案 / API          │
└──────────────────┬───────────────────────────────────┘
                   │
   浏览器（五张大屏）· 程序（/api/data/* 取数）
```

**两个数据入口汇入同一条流水线**：GitHub push（代码/数据仓库）触发服务器 autopull；本机定时产出（评测/测试/监控存档）经 scp 推给服务器。二者都由 server_pipeline.sh 加工后呈现在大屏与 API 上。

## 二、数据中台（底座）——三层加工 + 适配器接入

### 2.1 适配器接口（多项目通用性的根基）

```
数据中台/projects/*.json   ← 每个项目一份描述文件
{ "project_id", "name",
  "root": {"Windows": "...", "Linux": "..."},   ← 按操作系统选根
  "license": {...},
  "sources": [ {id, kind, path, pattern, required, desc}, ... ] }
        │
        ▼
collect.py（采集器）
  EXTRACTORS 注册表：11 种抽取器（@extractor 装饰器注册）
  json_dir / jsonl_dir / jsonl_file / json_file / markdown / markdown_dir
  / file_dir / coverage_xml / test_dir / git_log / toml_file
  每次采集：存在性校验 → SHA-256 指纹 → 记录数/大小/mtime → 变更检测
        │
        ▼
  ODS 快照（逐来源落盘）+ provenance.json（溯源档案）
```

**接入新项目 = 写一份 projects/*.json，核心代码零改动**（M1 已验证：知识库/codex-zcode-team 两个项目当天接入）。

当前接入：**3 项目 / 21 类来源**——vibememory(15) + knowledge-base(2) + codex-zcode-team(3)，双环境均「21 正常 / 0 异常」。

### 2.2 三层加工（build_assets.py）

```
ODS 原始层（快照+指纹，不改数值）
  → DWD 明细层（清洗/规范化/炸开）
      dwd_experiments     102+（实验逐文件）
      dwd_eval_items      7,731+（评测逐题，直读 runs 原文炸开 items）
      dwd_test_cases      4,153+（junit 逐用例）
      dwd_eval_runs / test_runs / obs_runs / evalsets / datasets ...
  → DWS 汇总层（面向应用的指标主题）
      dws_repo_health / experiment_metrics / eval_summary / weekly（周对比）
```

- **版本三元组**：每个资产带 `{upstream_revision, pipeline_commit, dataset_sha256}`
- **血缘事件**：collect/build_assets 每次运行发 OpenLineage 风格事件，追加 `assets/lineage_events.jsonl`；API `/api/data/lineage` 可查
- **记账特性（重要）**：records_total 是全量重建资产行数，同评测集重跑不涨行——增长刻度用 lineage 逐日事件数与 runs 存档数

### 2.3 质量与信号

```
quality.py：六性检查（完整/唯一/一致/准确/及时/有效）
  → 12 个资产逐一打分 → 综合分（当前 0.996 PASS）
signals.py：七类异常信号（每天流水线末尾自动跑）
  数据停更(评测/测试/监控 >48h warn >96h bad)
  / 来源健康 / 质量门禁(<0.85) / 测试门禁(FAIL)
  / 项目新鲜度(kb/cz，14 天 warn 28 天 bad)
  / 服务心跳(>5min)
  → assets/signals.json → 大屏「🚨 运行信号」面板 + /api/data/signals
```

## 三、三个能力中台

### 3.1 评测中台（质量——"系统答得好不好"）

```
评测集三层来源：
  内建 7 套（人工设计）+ 生成 7 套（固定种子，锚点全池唯一）
  + 公开基准转换（convert_benchmarks.py，4 个 target）：
    locomo_c01-c10（召回协议）· longmemeval_s_subset30/470
    locomo_adversarial（446 对抗题，含诱饵答案）★新
    longmemeval_abs（30 拒答题，expected_abstain）★新
    personamem_val（9 题个性化偏好，3 persona 样例）★新
        ▼
run_eval.py（召回评测，每日管线，秒级）
  VibeMemory 注入（pooled 共享实例 / isolate 逐题隔离）
  → recall(TF-IDF precision, Top-5)
  → 规则判分（metrics.py judge_item：会话 ID+关键词+陷阱词）
  → 指标聚合 + Wilson 95% CI → 门禁（gate.py 基线对比）
        ▼
run_answer_eval.py + llm_judge.py（答案级评测，GPU ~50 分钟/全量）★新
  召回 top-K → Qwen3-4B(NF4) 生成回答 → LLM 判语义
  ├ 对抗协议：adversarial_answer 是诱饵；正确行为=依据证据纠偏
  │   判定 correct(纠偏)/partial(避坑未纠偏)/wrong(中计)
  └ 拒答协议：对比参考弃答话术，判 abstain_ok/fail
  存档 runs/ans-*.json（增量落盘）→ 大屏「🧠 答案级评测」面板
```

首轮基线（2026-11-11）：对抗显式纠偏率 10/446（2.2%，生成侧过保守——明确改进方向）；拒答 29/30（96.7%）。

### 3.2 测试中台（回归——"改代码没改坏"）

```
run_tests.py：subprocess 在仓库 .venv 跑 pytest（basetemp 隔离）
  --scope quick（核心 5 文件秒级）/ --scope full（112 文件 1,360 用例，~7 分钟）
  → junit.xml 解析（通过率/失败明细）→ coverage.xml（行/分支）
  → 门禁（与上一轮通过率对比，容忍带 2pp）
  → 存档 test-*.json + junit/cov 证据文件
  → 覆盖率同步一份到仓库根 coverage.xml（数据中台来源）
```

### 3.3 监控中台（运行时健康——"跑起来快不快、稳不稳"）

```
collect_runtime_metrics.py：确定性混合负载（seed 可复现）
  1000 atoms（60% 事实/25% 决策/15% 偏好，锚点唯一防碰撞）
  → 逐条 store 计时 → flush_index → 400 次检索（70% 已知/30% 未入库）
  → 延迟分位数 + 命中率/零命中率 + MetricsCollector 降级事件
  → obs-*.json
```

## 四、运行时机制

### 4.1 本机（Windows）

```
任务计划程序 "VibeMemory中台定时产出"（每天 10:00，StartWhenAvailable 错过补跑）
    → scripts/scheduled/daily_runs.py
       幂等（当天已有存档→跳过）→ 三件套 → log() 双写(控制台+文件)
       → 增量同步（.sync_state.json 水位）→ scp → POST /api/refresh
手动入口：scripts/scheduled/手动跑一轮.bat
日志：logs/scheduled_YYYY-MM-DD.log（30 份滚动）
```

### 4.2 服务器（instabox）

```
systemd 用户服务 ×4：
  zhongtai   8080：pages/ 静态大屏 + 12 个 API + POST /api/refresh（互斥锁）
  archive    8081：全档浏览（文件下载）
  autopull   每 15 分钟 git fetch → 新提交自动跑流水线
  keepalive  每 10s 自访问（防睡眠）+ 心跳落盘
             + 连续 6 次失联自动重启对应服务（自愈）+ signals.log
隧道：cloudflared ×2（trycloudflare 快速隧道，会被 Cloudflare 回收
      —— start-zhongtai.sh 健康检查驱动：活着复用，挂了重开）
```

### 4.3 对外 API（12 端点，全部 GET/JSON）

```
/api/data/overview   总览（项目/来源/资产/质量/端点自述）
/api/data/catalog    资产目录+血缘    /api/data/provenance  溯源指纹
/api/data/quality    质量六性         /api/data/cards       数据集卡
/api/data/lineage    血缘事件         /api/data/weekly      周对比
/api/data/signals    异常信号         /api/data/diff        两日比对
/api/data/ods/<id>   单来源快照        /api/data/runs/<kind> 存档清单+单档
安全：source_id/文件名白名单正则（路径穿越拦截）；404/500 JSON 兜底
```

## 五、关键设计决策

| 决策 | 理由 |
| --- | --- |
| 纯标准库 + 单文件服务，一台 instabox | 零常驻重组件（明确不上 DataHub/Spark/Flink） |
| 全部数据内嵌大屏、离线可开 | 无网络也能看；国内网络不依赖 CDN |
| 适配器接口（projects/*.json + EXTRACTORS） | 新项目/新数据形态只加描述文件或注册一个函数 |
| 答案级评测独立执行器（不入每日管线） | GPU 重活（~50 分钟）与秒级召回评测解耦 |
| 对抗题「诱饵」判分协议 | 数据实锤：adversarial_answer 是表面答案，金标行为=纠偏 |
| Unknown=partial 一致规则 | 消除同答不同判（判分可信性的底线） |
| 增长刻度用 lineage 逐日事件/runs 存档数 | records_total 全量重建不涨行（记账特性，非 bug） |
| 数据比对 API（借鉴 AllData） | 两天之间变了什么，一条查询说清（审计刚需） |
