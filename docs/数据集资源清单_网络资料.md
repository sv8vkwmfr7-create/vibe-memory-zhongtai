### 本章接入注意事项

- LoCoMo 的 QA category 1-5 需自行查表映射为能力维度；每题的 `evidence` 为 `dia_id` 列表，转证据检索 gold 时保留会话号+轮次定位。
- LongMemEval 请用 **cleaned 版**（官方声明移除了干扰正确性的噪声会话）；若复现论文数字需回到原版，两版分数不可混比。
- MemoryAgentBench 的 recsys 任务需要额外的 `entity2id.json`；longmemeval 子任务用 GPT-4o LLM-judge。
- LoCoMo 为 **CC BY-NC 4.0**：构建对外分发的评测集时注意非商业条款；LongMemEval（MIT）/MemoryAgentBench（MIT）无此限制。
- MemBench 数据在百度网盘/Google Drive，CI 环境自动下载不稳定，建议先落盘到内部数据仓。

### 本章接入注意事项

- 多跳 QA 的"证据"有三种粒度：HotpotQA 是**句子级** supporting facts、2Wiki 是**三元组/推理步骤级**、MuSiQue 是**段落级** support——中台的证据 gold 结构要按粒度分别建表。
- distractor 设定下每题自带 ~10 段干扰文档，恰好可以模拟"记忆库里检索 top-k"的场景：k=2/5/10 分档跑 Recall@k。
- HotpotQA 为 CC BY-SA 4.0：若评测集与内部数据混用，注意 share-alike 传染性；2Wiki（Apache-2.0）/MuSiQue（CC BY 4.0）限制更松。
- TimeQA 原仓库失联，代码与数据只走 HF 镜像，引用时注明版本快照。
- TempLAMA 只输出完形填空查询，没有语料库，只能做"时序知识"诊断题，不能做检索评测。

## 6. 对 VibeMemory 评测中台的接入建议

### 6.1 统一会话级 JSONL Schema 建议

```jsonc
// 每行一个"评测实例"：一个会话库 + 一组问题
{
  "case_id": "locomo-0003",
  "source": "locomo",
  "source_version": "2024-main@<commit>",
  "license": "CC-BY-NC-4.0",
  "sessions": [
    {
      "session_id": "s01",
      "timestamp": "2023-05-07T21:00:00",
      "turns": [
        {"turn_id": "s01_t03", "speaker": "speaker_a", "text": "..."}
      ]
    }
  ],
  "questions": [
    {
      "q_id": "locomo-0003-q7",
      "question": "What did Melanie plan for Spring break?",
      "q_category": "temporal",          // single_hop|multi_hop|temporal|open_domain|adversarial|preference
      "gold_answers": ["Going to Boston"],
      "evidence": ["s01_t03", "s06_t11"], // dia_id / turn_id 列表；无证据标注则留空
      "answerable": true,                 // false → 拒答评测
      "judge": "f1"                       // f1|exact_match|substring|llm_judge|choice
    }
  ]
}
```

转换映射速查：LoCoMo `session_<n>`/`dia_id` → sessions/turns；LongMemEval `haystack_session_*` + `question_date/answer_date` → 同上；MemoryAgentBench 按任务块展开；BEIR/HotpotQA 等**无会话结构**的数据以"单会话单题"降级接入（sessions 为文档袋）。

### 6.2 可直接转成「会话级 JSONL 评测集」（会话流 + 问题 + 证据标注齐全）

| 数据集 | 理由与转换要点 |
|---|---|
| **LoCoMo** | 首选。`conversation`（session 时间戳 + dia_id）→ 会话流；`qa[].evidence`（dia_id 列表）→ 证据 gold；category 1-5 → 单跳/多跳/时序/开放域/拒答五个子集。注意 CC BY-NC 4.0，评测集若对外分发需遵守非商业条款 |
| **LongMemEval-cleaned** | `longmemeval_s_cleaned`（~115k tokens）做常规回归、`longmemeval_m_cleaned`（~500k）做压力、`longmemeval_oracle` 做检索上限对照（oracle vs S 的差距 = 检索损失）。题干自带 question_date/answer_date，时序通道直接可用 |
| **MemoryAgentBench** | 已是"增量多轮注入 + 多次提问"格式，HF 一键加载；AR/TTL/LRU/CR 四能力可直接对齐中台四个能力面板 |
| **THUIR MemoryBench** | HF DatasetDict（train/test），预测协议简单（test_idx/response/dataset）；on-policy regime 需要接用户模拟器，中台可只取其 off-policy 数据做静态评测 |
| **PersonaMem** | 交互历史 + 演化偏好，适合"用户画像漂移"场景；多选题部分可自动判分，开放式部分需 LLM 判分 |
| **MSC 镜像** | 有会话摘要、无 QA 标注——建议只作语料源，用模板法自动造 QA 后打上"合成"标记 |

### 6.3 需要逐题隔离实例（防串扰/防泄漏，每题独立上下文与 qrels）

- **HotpotQA / 2WikiMultihopQA / MuSiQue**：采用 distractor 设定，每题独立提供 10 段干扰段落 + gold 段落；2Wiki/MuSiQue 的 evidence 字段可转图检索 gold path。题与题共用维基语料，中台必须按题缓存隔离实例，避免记忆系统跨题"记住"答案。
- **BEIR 子集**：corpus 全局共享，按子集建独立索引；建议选 NQ、HotpotQA、SciFact、FiQA、TREC-COVID 等异构 4-6 个做泛化回归。
- **NQ / TriviaQA**：开放域，需自配语料（维基快照或 MS MARCO 语料）并冻结版本。
- **RULER / NIAH / NoLiMa**：合成任务按 (任务, 长度, 针数) 配置生成实例；NoLiMa 必须做——它是唯一能证明"向量/图通道不是 BM25 换皮"的公开证据。
- **LongBench v2**：单条 context 很长（8k-2M），逐题隔离并缓存 context。
- **TimeQA / CMRC 2018 / DRCD / WebCPM**：每题附证据段落，独立成实例。

### 6.4 只适合答案级 LLM 判分（无法用检索指标直接评）

- **LoCoMo open-domain 类**、**PersonaMem 开放式个性化回答**、**WebCPM 长式回答**、**DuReader 描述类答案**：答案无唯一 gold，用 LLM-as-judge + 事实核查双通道。
- **MemoryAgentBench 的 longmemeval / infbench 摘要子任务**：官方即用 GPT-4o judge，直接复用其判分 prompt。
- **DialSim**：角色一致性 + 响应时延 + 记忆准确性混合判分，只适合在线模拟场景。
- **PrefEval**：偏好遵循本质是"行为评测"，judgement 应评最终回答是否违反偏好，而非检索命中。

### 6.5 指标协议建议（按题型分流）

| 题型 | 检索指标 | 答案指标 | 备注 |
|---|---|---|---|
| 有证据标注（LoCoMo/HotpotQA/2Wiki/MuSiQue/BEIR） | Evidence Recall@k、MRR、nDCG@10（按证据粒度建 gold） | F1 / EM | 检索与答案分两条曲线报告 |
| 多选/单选（LongBench v2、PersonaMem-MC、PrefEval、CMMLU） | Recall@k（可评） | choice accuracy | 最稳定，适合 CI 门禁 |
| 合成检索（RULER/NIAH/NoLiMa） | 针召回率 | substring/EM | 按长度分档出曲线 |
| 开放生成（LoCoMo open-domain、PersonaMem 开放、WebCPM、DuReader） | 不评检索 | LLM-judge（事实性+偏好遵循双维度） | 判分 prompt 固化并记录 judge 模型版本 |

### 6.8 常见工程陷阱

- **测试集污染**：HotpotQA/NQ/TriviaQA 大概率已在预训练语料中出现，评记忆系统时答案可能来自模型参数而非检索——建议报告"检索证据命中率"与"答案正确率"两个数，若两者显著背离即污染信号。
- **许可冲突**：CC BY-SA（HotpotQA、NQ）有 share-alike 传染性；CC BY-NC（LoCoMo）与 Adobe Research License（NoLiMa）禁商业；评测集再分发前统一过一遍许可清单。
- **版本漂移**：LongMemEval 原版 vs cleaned 版、LoCoMo 50 段旧版 vs 10 段正式版分数不可比；JSONL 里必须写 `source_version`。
- **真实用户数据**：MSC、DuReader 含真实人机对话，内部使用注意 PII 与数据条款。
- **大文件隔离**：MS MARCO v2.1（28GB）、NQ 原生版（几十 GB）等大包解压到独立目录，脚本与数据分离。
