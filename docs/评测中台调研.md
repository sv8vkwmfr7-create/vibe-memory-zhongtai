## 1. 记忆评测基准

### 1.1 LoCoMo（长对话记忆评测，事实上的行业默认基准）

- **论文**：*Evaluating Very Long-Term Conversational Memory of LLM Agents*，arXiv:2402.17753，Adyasha Maharana 等（UNC / Snap Research 背景），ACL 2024。检索确认：https://arxiv.org/abs/2402.17753
- **数据构成**（来自 arXiv 摘要页与官方仓库 README 抓取，2026-11-08）：
  - 共 10 段机器辅助生成、人工校验的长对话；每段对话平均约 300 轮、约 9K tokens，最多跨越 35 个会话，以「人设 + 时间事件图」作为 grounding。
  - 三类任务：**问答（QA）**、**事件摘要（event summarization）**、**多模态对话生成**。
  - QA 按四类组织：**single-hop / multi-hop / temporal / adversarial**（adversarial 问的是对话中从未出现的信息，考察能否「不编造」——与 LongMemEval 的 abstention 同源）。Mem0 官方研究页将 LoCoMo 概括为「1,540 questions, 5 categories」（即上述分类再细分），见 https://mem0.ai/research 。
  - 注意：官方 README **未**给出每类 QA 的具体数量与逐类指标定义，需查论文正文或数据文件 `./data/locomo10.json`（本次未逐条核实）。
- **官方指标**：论文对 QA 采用 LLM 判分（GPT-4 judge）+ 人工校验的正确率口径，事件摘要使用 F1 类指标（摘要页未展开，需查正文）；后续工作（Mem0/Zep）普遍沿用 **LLM-as-a-Judge（J 分数）**。官方仓库未在 README 中列出指标公式。
- **代码仓库**：https://github.com/snap-research/locomo （README 明确 ACL 2024 论文数据与代码，评测脚本含 `evaluate_gpts.sh`、`evaluate_rag_gpts.sh`；事件摘要与多模态生成部分标注 "Coming soon!"）。项目页：https://snap-research.github.io/locomo/ 。许可证 CC BY-NC-SA 4.0。
- **重要工程提醒（分数争议）**：各家在 LoCoMo 上的「SOTA」口径互相矛盾——Mem0 论文报告 ~92.5 分；Zep 发表反驳文章称按其协议 Zep 高出 Mem0 约 24%，并质疑 LoCoMo 本身的统计可靠性。做中台时**必须固定自己的评测协议（judge 模型、prompt、K 值、子集）**，不可直接引用厂商分数。
  - Zep 反驳文：*Lies, Damn Lies, & Statistics: Is Mem0 Really SOTA in Agent Memory?*（2025-05-06）https://www.getzep.com/blog/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory
  - Reddit 讨论：https://www.reddit.com/r/LangChain/comments/1kg5qas/
  - Mem0 回应/对比页：https://mem0.ai/library/agent-memory/zep-vs-mem0-which-ai-memory-layer-should-you-choose

### 1.2 LongMemEval（ICLR 2025，五种核心能力维度）

- **论文**：*LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory*，arXiv:2410.10813，Di Wu 等（UCLA + Tencent AI Lab Seattle），ICLR 2025。检索确认：https://arxiv.org/abs/2410.10813
- **构成**（arXiv 摘要页直接确认）：500 个精心策划的问题，嵌入可自由扩展的用户-助手聊天历史；问题分 7 种题型；**五种核心能力**：
  1. **信息抽取**（information extraction）
  2. **多会话推理**（multi-session reasoning）
  3. **时间推理**（temporal reasoning）
  4. **知识更新**（knowledge updates：新信息覆盖旧信息）
  5. **拒答**（abstention：信息不存在时应拒绝回答）
- **规模版本**：LongMemEval-S（约 115k tokens）与 LongMemEval-M（约 500k tokens 交互历史）（来自检索结果摘要，与官方仓库一致）。
- **关键发现**：商用聊天助手与长上下文 LLM 在其上「30% accuracy drop」；论文提出把长期记忆分解为 **索引 / 检索 / 阅读** 三阶段，并用会话分解、事实增强键扩展、时间感知查询扩展提升召回与 QA。
- **代码仓库**：https://github.com/xiaowu0162/LongMemEval
- **对 VibeMemory 的意义**：五能力可直接映射为记忆中台的**能力维度门禁**——「时间推理」对应时序检索策略，「知识更新」对应记忆分片的生命周期/失效标签，「拒答」对应图 PPR 召回不足时的 abstention 行为。

**来源**
- https://arxiv.org/abs/2410.10813
- https://github.com/xiaowu0162/LongMemEval

### 1.4 记忆系统论文的评测协议与分数

#### Mem0（arXiv:2504.19413，ECAI 2025）

- **论文**：*Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory*，Prateek Chhikara 等。https://arxiv.org/abs/2504.19413
- **评测协议**（arXiv 摘要页确认）：在 **LOCOMO** 上与六类基线对比——记忆增强系统、不同 chunk/参数的 RAG、全上下文、开源记忆方案、专有模型、专用记忆平台；指标为 LLM-as-a-Judge。
- **关键数字**（摘要原文）：
  - 相对 OpenAI memory：LLM-judge 指标**相对提升 26%**；
  - 图变体 **Mem0g 比基础版整体高约 2%**；
  - 相对 full-context：**p95 延迟降低 91%、token 成本节省 90% 以上**。
- **官方研究页分数**（https://mem0.ai/research ，2026-11-08 抓取）：LoCoMo 综合 92.5（单跳 94.6 / 多跳 95.4 / 开放域时序 82.3 / 时序 92.5），平均 token 6,956 vs full-context 25,000+；LongMemEval 94.4（无基线对照）。
- **仓库**：https://github.com/mem0ai/mem0
- **注意**：其评测仅用 LoCoMo 10 段对话子集，且与 Zep 的分数互相矛盾（见 1.1 争议条目）；中台引用时须注明协议。

#### Zep / Graphiti（arXiv:2501.13956）

- **论文**：*Zep: A Temporal Knowledge Graph Architecture for Agent Memory*，Preston Rasmussen 等（Zep 团队）。https://arxiv.org/abs/2501.13956
- **系统**：核心引擎 **Graphiti**，时序感知知识图谱，动态融合非结构化对话与结构化业务数据，**保留历史关系**（摘要强调 "maintaining historical relationships"；社区通常称 bi-temporal 双时态建模）。
- **关键数字**（摘要原文，2026-11-08 确认）：
  - **DMR 基准**（MemGPT 团队设立）：**94.8% vs 93.4%** 胜过 MemGPT；
  - **LongMemEval**：准确率最高**提升 18.5%**；
  - 延迟比基线**降低 90%**。
- **仓库**：Graphiti 开源库为 `getzep/graphiti`（本次检索未直接打开该仓库页面，未核实 README 内容，仅列项目名）。

#### A-MEM（arXiv:2502.12110）

- **论文**：*A-MEM: Agentic Memory for LLM Agents*，W. Xu 等，NeurIPS 2025 poster（检索结果表述）。https://arxiv.org/abs/2502.12110
- **机制**：受 **Zettelkasten** 卡片盒法启发，新记忆到达时自动触发**链接生成（link generation）**与**记忆演化（memory evolution）**，构成动态互联的知识网络。检索结果提及代码库 `agiresearch/A-mem`。
- **说明**：其在 LoCoMo 上的具体分数本次未核实（需读论文实验章节）。

#### MemoryBank（arXiv:2305.10250）

- **论文**：*MemoryBank: Enhancing Large Language Models with Long-Term Memory*，W. Zhong 等（2023）。https://arxiv.org/abs/2305.10250
- **机制**：类人长期记忆的存/取/更新，带**艾宾浩斯遗忘曲线**式衰减机制；落地为长期陪伴聊天机器人 **SiliconFriend**。检索结果称代码/demo 在 GitHub（本次未核实主仓库地址）。

## 2. 检索 / 问答通用指标与 RAG 评测框架

### 2.1 经典 IR 指标：Recall@K、MRR、nDCG

- **Recall@K**：前 K 条结果命中的相关文档占全部相关文档的比例；最直观的检索召回指标（VibeMemory 多策略融合的上游把关指标）。
- **MRR（Mean Reciprocal Rank）**：第一个相关结果排名倒数的均值，考「第一条命中出现得多早」。
- **nDCG@K**：带分级相关性与对数折损的排序质量指标，对理想排序归一化；Stanford CS276 讲义称其为「研究中 perhaps the most commonly used measure」。
- **综述/教程类来源**：
  - Weaviate 博客《Evaluation Metrics for Search and Recommendation Systems》（precision/recall/MRR/MAP/NDCG 逐个讲解）：https://weaviate.io/blog/retrieval-evaluation-metrics
  - Stanford CS276 评测讲义（PDF）：https://web.stanford.edu/class/cs276/handouts/EvaluationNew-handout-1-per.pdf
  - Fabian Hertwig《Metrics for Information Retrieval》（MRR@k / NDCG@k 定义）：https://fabian-hertwig.de/blog/retrieval-metrics/ （注：该链接来自检索结果描述，域名未经本次打开核实）
- **检索模型零样本评测基准 BEIR**：*BEIR: A Heterogeneous Benchmark for Zero-shot Evaluation of Information Retrieval Models*（arXiv:2104.08663，2021），统一 18 个数据集、9 类检索任务；结论「BM25 是强基线」。仓库含统一评测 harness：https://github.com/beir-cellar/beir —— 对中台的启示：**检索层离线评测可直接复用 BEIR harness 的指标实现**。

**来源**
- https://weaviate.io/blog/retrieval-evaluation-metrics
- https://web.stanford.edu/class/cs276/handouts/EvaluationNew-handout-1-per.pdf
- https://arxiv.org/abs/2104.08663
- https://github.com/beir-cellar/beir

### 2.2 BLEU / ROUGE 的局限性

- **ROUGE 原始论文**：Lin 2004，*ROUGE: A Package for Automatic Evaluation of Summaries*，https://aclanthology.org/W04-1013 （n-gram 重叠类指标的起点）。
- **BLEU 的批评**：Freitag 等（Google），*BLEU might be Guilty but References are not Innocent*（EMNLP 2020），arXiv:2004.06063，https://arxiv.org/abs/2004.06063 —— 指出 BLEU 低分一半责任在低质量/数量不足的参考答案，提出语义化参考集。
- **摘要评测再审视**：Bhandari 等，*Re-evaluating Evaluation in Text Summarization*（EMNLP 2020），arXiv:2010.07100，https://arxiv.org/abs/2010.07100 —— 文中点明「近 20 年 ROUGE 是摘要评测事实标准」，并证明更新参考集与评测方式后与人工一致性显著变化。
- **对话系统评测的反面教材**：Liu 等，*How NOT to Evaluate Your Dialogue System: An Empirical Study of Unsupervised Human Evaluation Metrics*（EMNLP 2016），arXiv:1603.08023（本次检索结果仅提及标题未给出链接，arXiv 号未打开核实）。
- **工程结论**：BLEU/ROUGE 与人工判断相关性弱、依赖参考答案质量，对记忆系统的**生成侧**只宜作回归监控的辅助信号，结论性判定应以 LLM-judge + 人工抽样为主。

**来源**
- https://aclanthology.org/W04-1013
- https://arxiv.org/abs/2004.06063
- https://arxiv.org/abs/2010.07100

### 2.3 RAGAS（RAG 管线组件级评测）

- **论文**：*RAGAS: Automated Evaluation of Retrieval Augmented Generation*（2023-09），https://arxiv.org/abs/2309.15217
- **官方指标清单**（docs.ragas.io，2026-11-08）：https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/
  - **Faithfulness（忠实度）**：回答与检索上下文的事实一致性（0-1）；
  - **Answer/Response Relevancy（答案相关性）**：由答案反向生成问题再算相似度的口径；
  - **Context Precision（上下文精度）**：检索内容与答案的相关排序质量；
  - **Context Recall（上下文召回）**：检索内容对参考答案的覆盖度；
  - 另有 Context Entities Recall、Noise Sensitivity、多模态版本等。
- **仓库**：https://github.com/explodinggradients/ragas
- **对 VibeMemory 的映射**：Faithfulness≈生成不编造；Context Precision/Recall≈检索侧质量；Noise Sensitivity≈图 PPR 召回噪声的敏感性，都可直接搬进指标体系。

**来源**
- https://arxiv.org/abs/2309.15217
- https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/
- https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness
- https://github.com/explodinggradients/ragas

### 2.4 TruLens（RAG Triad 与 Agent 评测）

- **RAG Triad**（官方概念页）：https://www.trulens.org/getting_started/core_concepts/rag_triad
  - **Context relevance**：检索上下文是否切题（考检索器）；
  - **Groundedness**：答案是否被上下文支撑（考生成器，防幻觉）；
  - **Answer relevance**：最终答案是否回应了问题（端到端）。
- 另有可扩展 feedback functions（NLI 版 groundedness、moderation 等）与 Agent 评测（Plan Adherence、Tool Selection）：https://www.trulens.org/component_guides/evaluation/feedback_implementations/custom_feedback_functions
- **定位**： tracing + 反馈函数框架，适合把「RAG 三角」当作记忆系统的日常回归集。

**来源**
- https://www.trulens.org/getting_started/core_concepts/rag_triad
- https://www.trulens.org/component_guides/evaluation/feedback_implementations/custom_feedback_functions

## 3. 评测平台 / 中台层实践

### 3.1 OpenCompass（上海人工智能实验室「司南」）

- **仓库**：https://github.com/open-compass/opencompass （中文 README：https://github.com/open-compass/opencompass/blob/main/README_zh-CN.md ）
- **官网/榜单/评测集社区**：https://opencompass.org.cn ；CompassHub：https://hub.opencompass.org.cn/home ；CompassRank：https://rank.opencompass.org.cn/home ；文档：https://opencompass.readthedocs.io/zh_CN/latest/index.html
- **能力概览**（中文 README 抓取，2026-11-08）：一站式大模型评测平台；支持 OpenAI/Anthropic/Gemini/Qwen/GLM/DeepSeek 等模型与 HuggingFace/LMDeploy/vLLM 推理后端；集成 100+ 数据集，覆盖知识、推理、代码、科学、语言、长上下文、安全等能力维度；支持零样本/少样本/思维链/规则/LLM Judge 等评测方式；任务可切分、并发、分布式执行。
- **架构**（官方 framework overview 抓取：https://opencompass.readthedocs.io/en/latest/user_guides/framework_overview.html ）：一次评测 = **评测配置（models + datasets + infer/eval/summarizer）→ Partitioner 任务切分 → Runner 调度执行（推理→评测→汇总）→ Summarizer 结果汇总**；产物分 `predictions/`、`results/`，支持 `--reuse` 断点续跑。文档原句提醒：「Model version, data version, dependency environment, random arguments, and Judge model all affect results」——这正是中台要管理的可复现性要素。
- **重要勘误**：任务清单中要求的「模型层/任务层/能力层」三层架构说法，**在 OpenCompass 官方文档与 README 中均未查到对应原文**；官方以「配置—分区—执行—汇总」流水线描述架构。该三层说法可能来自早期宣传稿/第三方文章，本次未查到出处。
- **论文引用格式**：README 给出 `@misc{2023opencompass, ...}`，另有完整 arXiv 论文（检索结果称其架构为配置系统/任务切分/执行调度/结果聚合/报告五个组件；该论文 arXiv 号本次未核实）。

### 4.3 数据污染 / 防泄漏

- **综述**：*Benchmark Data Contamination of Large Language Models: A Survey*（arXiv:2406.04244，Yale NLP），把 BDC 定义为「LLM 训练时见过评测数据导致分数虚高」，系统梳理预防与检测方法；配套仓库 https://github.com/yale-nlp/lm-contamination-survey ：https://arxiv.org/abs/2406.04244
- **工程含义**：对记忆中台而言，防污染不仅是「预训练泄漏」——还包括：评测集被业务方反复「对答案」过拟合、golden set 参与调参、同源数据在训练/评测两侧重复。缓解做法（来自综述与社区实践）：**密封评测集（sealed set，评测集不进训练/调参回路）、动态/改写式评测题、双门协议（先过密封集再过公开回归集）**。检索结果中「two-gate protocol」提法见于 HF Daily Papers 相关条目（未打开原文核实）。

### 4.4 LLM-as-a-Judge 的偏差与缓解

- **奠基论文**：Zheng 等，*Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena*（NeurIPS 2023 D&B），arXiv:2306.05685，https://arxiv.org/abs/2306.05685 —— 记录三大偏差：
  1. **位置偏差（position bias）**：成对比较时偏爱第一个（或固定位置）答案，GPT-4 对第一个回答的偏好可达 66-75%；缓解：**交换顺序重判（swap）后合并**；
  2. **长度/啰嗦偏差（verbosity bias）**：偏爱更长更详细的答案；
  3. **自偏好/自我增强（self-enhancement / self-preference）**：judge 偏爱同家族模型（自己）的输出。
- **位置偏差专门研究**：*Large Language Models are not Fair Evaluators*（Wang 等，ACL 2024），arXiv:2305.17926，https://arxiv.org/abs/2305.17926 —— 提出 Balancing（多次交换位置打分再合并）显著降低位置偏差、提升与人类一致率。
- **系统性量化**：Shi 等，*A Systematic Study of Position Bias in LLM-as-a-Judge*，arXiv:2406.07791（成对/列表两种设定下的重复稳定性等度量）；Wataoka 等，*Self-Preference Bias in LLM-as-a-Judge*，arXiv:2410.21819（量化自偏好，指出其与位置/长度偏差在 Arena 类基准中的交互）。两篇 arXiv 号来自检索结果，摘要页未逐条打开核实。
- **中台落地规则**：judge 必须固定模型与 prompt 版本；成对评测强制 swap；用与被评系统不同家族的 judge；关键结论抽样人工复核；记录 judge 配置进实验元数据（呼应 OpenCompass 文档「Judge model 影响结果」）。

### 4.5 回归门禁（CI 中的 eval gate）

- **定义**（社区教程，agentswarms.fyi）：eval gate = 「当 prompt/模型/工具变更引发回归时阻断部署的 CI 步骤」，https://agentswarms.fyi/learn
- **典型实现**：
  - promptfoo 官方 GitHub Action：PR 时跑「修改前 vs 修改后」对比，结果以 PR 评论回贴，断言回归即 fail：https://www.promptfoo.dev/docs/integrations/github-action ；CI/CD 总览（gate 部署）：https://www.promptfoo.dev/docs/integrations/ci-cd
  - EvaliQA RAG 实战指南：给出 `.github/workflows/eval-gate.yml` 示例——每个 PR 在小规模人工精选 golden 集（约 "golden forty"）上跑评测并与基线比较，指标回退则挡合并：https://evaliqa.com/resources/evaliqa-rag-evaluation-guide.pdf
- **方法论**：Braintrust《What is eval-driven development》（评测即 LLM 应用的“工作规格”，改动前先评测）：https://www.braintrust.dev/articles/eval-driven-development
- **平台侧**：LangSmith 产品页明确把「catch regressions」作为评测平台的核心卖点：https://www.langchain.com/langsmith/evaluation
- **中台要点**：门禁三要素——**固定 golden 集（版本化）+ 稳定 judge 配置 + 与基线（baseline experiment）的显式阈值比较**；小而准的 golden 集优先于大而脏的集合（成本与抖动考虑）。

## 5. 数据中台对接：数据质量「六性」出处确认

### 5.1 GB/T 36344-2018《信息技术 数据质量评价指标》

- **官方全文**（国家标准全文公开系统，在线预览）：https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=D12140EDFD3967960F51BD1A05645FE7
- **标准规定的六大评价指标**（检索确认，2026-11-08）：**规范性、完整性、准确性、一致性、时效性（及时性）、唯一性**。各指标定义：规范性=符合数据标准/数据模型/业务规则/元数据的程度；完整性=数据元素被赋予数值的程度；准确性=准确表示真实实体(实际对象)的程度；一致性=与其他特定上下文中使用的数据无矛盾的程度；时效性=数据在时间变化中的正确程度/满足使用要求的及时程度；唯一性=数据记录在特定范围内不重复的程度。
- **重要差异说明**：任务清单中的「有效性（validity）」**不在** GB/T 36344 的六指标中；GB/T 的第六项是「规范性」。六性含「有效性」的说法实际对应 **DAMA** 的框架（见下）。CSDN 标准解读佐证：https://blog.csdn.net/qq_42393720/article/details/138327129

### 5.2 DAMA（数据管理协会）六核心维度

- **DAMA International 六核心维度**：**Accuracy（准确性）、Completeness（完整性）、Consistency（一致性）、Timeliness（及时性）、Uniqueness（唯一性）、Validity（有效性）**——与任务清单的「六性」完全对应。IBM 文档对 DAMA 六维度的转述：https://www.ibm.com/docs/en/ws-and-kc?topic=quality-data-dimensions
- **扩展**：DAMA-DMBOK 2.0 常被解读为在六维之外再加 Currency、Integrity、Reasonableness 等；系统性目录见 DAMA-NL《Dimensions of Data Quality》研究论文（2020-09，113 页 PDF）：https://www.dama-nl.org/wp-content/uploads/2020/09/DDQ-Dimensions-of-Data-Quality-Research-Paper-version-1.2-d.d.-3-Sept-2020.pdf
- **相关标准**：ISO/IEC 25012（数据质量模型）常与 GB/T 36344 并列引用（检索结果提及，ISO 原文页未打开核实）。

### 5.3 对评测集资产管理的映射

把六性用于评测集治理（结合第 4.2/4.3 节）：
- **完整性**：每条评测样例的字段齐备（query/期望答案/时间标签/关系标签/证据）；
- **唯一性**：跨评测集去重，防同题多版本造成回归误报；
- **一致性**：同一能力的多份评测集口径一致（指标、judge prompt、K 值）；
- **准确性**：golden 答案人工校验、定期复审；
- **及时性**：知识更新类样例（呼应 LongMemEval 的 knowledge updates）需要维护「当前有效答案」并记录失效时间；
- **有效性/规范性**：样例格式符合中台 schema，judge 输出可解析。

## 6. 对 VibeMemory 评测中台的分层次启示（简要）

1. **检索层（多策略逐个 + RRF 融合）**：以 Recall@K / MRR / nDCG 为离线主指标，直接复用 BEIR harness 的实现口径（2.1）；BM25 是必须保留的强基线。
2. **生成层**：RAGAS 忠实度 + TruLens RAG Triad（context relevance / groundedness / answer relevance）作为日常回归集（2.3、2.4）；BLEU/ROUGE 只作辅助趋势信号（2.2）。
3. **记忆能力层**：LoCoMo 的 four QA 类别 + LongMemEval 五能力（尤其 temporal reasoning、knowledge updates、abstention——正好压在 VibeMemory 的关系标签、分片生命周期与 PPR 拒答行为上）（1.1、1.2）；进阶可选 MemBench 的反思记忆维度（1.3）。
4. **中台工程层**：学 OpenCompass 的「配置→分区→执行→汇总」流水线与断点续跑（3.1）；学 LangSmith 的评测集自动版本化（3.4、4.2）；回归门禁用 promptfoo/自研 eval-gate.yml 落进 CI（4.5）。
5. **可信层**：LLM-judge 三偏差的强制缓解规则（4.4）+ 评测集密封/双门防污染（4.3）+ 数据质量六性作为评测集资产的准入检查（5）。
