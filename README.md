# VibeMemory 四中台 · 多项目可信数据集管理平台

数据 / 评测 / 测试 / 监控四个中台：采集（SHA-256 指纹+变更检测）→ 分层资产（ODS/DWD/DWS）→ 质量六性 → 数据集卡（哪来的/哪版本/能不能用）→ 血缘事件 → 五张可视化大屏 + 12 个数据 API。多项目适配器：`数据中台/projects/*.json` 写一个文件即接入新项目。

- **运行形态**：一台 instabox 云盒 + 本机 Windows（每天 10:00 定时产出），零常驻重组件
- **源码结构**：`数据中台/`（采集与资产）、`评测中台/`（召回评测 + LLM-judge 答案级评测）、`测试中台/`（pytest 回归门禁）、`监控中台/`（运行时负载）、`scripts/`（大屏生成器 + 服务器脚本 + 定时产出）
- **大屏**：`pages/` 为静态产物（数据内嵌、离线可开），由 `python scripts/build_pages.py` 从资产生成
- **验收基线**：2026-11-15 起指标以新口径存档为准（含代码版本 revision；旧存档仅参考）
- **说明文档**：`README-中台.md`（部署与使用）、`docs/`（架构/调研/阶段目标；交接文档含凭证不入库）

## 两份笔记的核心结论速览

**数据中台**
1. 本质是"数据能力复用机制" = 方法论 + 平台工具 + 组织运营，目标是「使数据产生业务价值」（信通院《数据中台实践指南 1.0》）。
2. 起源：2015 马云参访 Supercell → 张勇「大中台，小前台」→ 2019 "数据中台元年" → 2023 理性化、标准化。
3. 与数仓/数据湖/湖仓一体是分层互补关系，不是"更大的数仓"。
4. 成败关键在组织与运营（一把手工程、三阶段建设、持续运营），而非技术选型。
5. "拆中台"是组织形态纠偏，统一标准/统一服务/资产化的内核以云上数据平台（湖仓一体 + AI）继续演进。

**测试中台**
1. 中台建设有规模门槛：用例上万、测试占交付 30%+ 时才值得自研（美团外卖参照值）。
2. 方法论核心是"能力下沉成基础设施"：阿里把数据（影子表）、环境（灰度隔离）、RBC（按请求代码覆盖）沉淀为"测试水电煤"。
3. 关键工程教训：录制回放必须"可编辑"、数据一致性决定回放成功率、平台核心服务必须无状态。
4. 主流开源底座：MeterSphere（持续测试）、HttpRunner、Sonic（云真机）、JMeter/Playwright 等组合成平台。
5. 最大变量是 AI：大模型当测试预言（美团 KuiTest，ICSE 2025）、平台内置 AI 生成用例、造数服务 MCP 化。
